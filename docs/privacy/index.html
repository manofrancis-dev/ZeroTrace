Privacy notes

Privacy and data handling

Zero Trace is a security tool, so its data handling should be clear before you paste a link. This page explains what the scanner processes, what it does not store, and which third parties are involved.

Updated 27 November 2026No analytics installedRead before scanning

Do not scan private, confidential, authenticated, or personal URLs. A scan sends the URL to the backend and to third-party services. VirusTotal’s documentation says submitted or queried items may be added to its dataset.

Summary

  • Zero Trace does not maintain a scan-history database and does not offer saved results.
  • Scan API responses are marked no-store.
  • A functional session cookie authorizes the scan. It is not an advertising or analytics cookie.
  • No analytics script is installed on this website.
  • The submitted URL is processed by the backend, VirusTotal and RDAP when configured, and an isolated browser sandbox.
  • Hosting providers may keep operational logs under their own policies.

What happens when you submit a URL

  1. Your browser sends the URL to the Zero Trace API over HTTPS.
  2. The API validates the URL, rejects private or reserved destinations, and strips URL-embedded credentials before external requests.
  3. When configured, the API queries VirusTotal for URL reputation and may request a fresh analysis. It queries RDAP for domain or IP registration context.
  4. The URL is opened in an isolated Chromium sandbox to observe redirects, page behavior, and downloads.
  5. The API returns a structured report to your browser. The response is marked no-store.

What Zero Trace stores

The Zero Trace application does not write submitted URLs or scan results to a database. There is no account system and no saved scan history. The API keeps an in-memory rate-limit counter per client address for a short rolling window; that counter does not contain the URL.

The hosting providers that run the frontend and backend may keep standard operational logs, such as request timestamps, IP addresses, and error information, under their own retention policies. Zero Trace does not control those logs. If you need to avoid any third-party processing, do not submit a URL.

Cookies

Zero Trace sets a functional cookie named zero_trace_session when you start a scan. It is HTTP-only, expires after the configured session lifetime (15 minutes by default), and is used only to authorize the scan request. On the hosted deployment it is marked Secure and, when the frontend and backend are on different sites, SameSite=None so the cross-site scan request can work.

This site does not set advertising cookies, analytics cookies, or third-party tracking cookies. Because only a strictly functional cookie is used, no consent banner is shown. If analytics or other non-essential tracking is added in the future, this page and the consent approach must be updated first.

Analytics

No Google Analytics, Bing tracking, advertising pixel, or other analytics script is installed on this website. If privacy-friendly analytics are added later, they should be configured to avoid collecting submitted URLs, scan results, query strings, or other sensitive data. This page will be updated before any such change.

Security measures

  • HTTPS for the website and API in the hosted deployment.
  • Signed, short-lived scan session cookies.
  • SSRF protection that rejects private, loopback, local, multicast, and reserved destinations.
  • URL credential stripping before external requests.
  • Rate limiting on the expensive scan endpoint.
  • No-store headers on scan API responses.
  • Network isolation for the browser sandbox.

These measures reduce risk but do not make scanning risk-free. Security is not a guarantee, and no service can promise that a third party will never experience an incident.

Your choices

  • Do not submit URLs that contain private, confidential, or personal information.
  • Use the official app or a known address instead of a link when you need to verify an account.
  • Clear the session cookie by closing the browser or clearing site data.
  • Use the FAQ and security guide without submitting a URL.

Questions or corrections

For privacy questions or corrections, open an issue on the Zero Trace GitHub repository. Do not include sensitive URLs or personal information in a public issue.

Changes to this page

This page is updated when the scanner’s data handling changes. The “Updated” date at the top reflects the latest review. Material changes should be described in the repository history.
