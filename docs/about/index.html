About the project

About Zero Trace

Zero Trace is an independent, free URL security scanner built around a simple idea: show the evidence, show the gaps, and never pretend that missing data means safe.

Independent projectBuilt by Mano Francis DevUpdated 27 November 2026

Why Zero Trace exists

Most people check a link by glancing at it, trusting a padlock, or searching for the site’s name. Those habits help, but they are easy to fake. At the same time, many security tools reduce a complex question to an opaque score or a green checkmark without explaining what was actually checked.

Zero Trace takes a different approach. It gathers evidence from several sources, reports which sources responded, and explains where coverage is missing. The goal is not to replace your judgment. It is to give you better information before you enter a password, payment detail, or personal information.

Who it is for

  • Everyday internet users who receive unexpected links by email, SMS, chat, or social media.
  • Students and beginners learning how URL structure, reputation, and phishing signals fit together.
  • Developers and small teams who want a quick second opinion on a public URL.
  • Security researchers who want to see provider states and evidence rather than a single verdict.

How it is built

Project components
ComponentImplementation
WebsiteStatic HTML, CSS, and JavaScript deployed with GitHub Pages.
APIPython FastAPI backend with signed scan sessions, rate limiting, input validation, and SSRF checks.
Browser analysisAn isolated Chromium sandbox that records redirects, page behavior, and download metadata.
EvidenceVirusTotal URL reputation and RDAP registration data, each with explicit availability states.
Frontend dependenciesNo framework and no external font or analytics script. The scanner UI is plain JavaScript.

What the score means

The score is an evidence summary on a 0–99 scale. It is not a probability, and 100 is intentionally never returned. When reputation or browser evidence is unavailable, the score is capped so that sparse coverage cannot look like certainty. RDAP is contextual intelligence, not a threat verdict, so it does not lift the score by itself.

Read the scan result guide for the verdict definitions, or the scoring section for the caps and correlation rules.

Privacy by design

Zero Trace does not maintain a scan-history database, and scan API responses are marked no-store. A functional session cookie is used to authorize the scan; it is not an advertising or analytics cookie. No analytics script is installed on this website.

The URL is still processed by the scanning backend and by the third-party services used for the scan. When VirusTotal analysis is enabled, the URL is sent to VirusTotal, whose documentation says submitted or queried items may be added to its dataset. Hosting providers may keep operational logs. Do not scan private or confidential URLs. The privacy notes explain this in detail.

Security boundaries

  • Private, loopback, local, link-local, multicast, and reserved destinations are rejected before scanning.
  • URL-embedded credentials are stripped before external requests.
  • Scan requests require a signed, short-lived session cookie.
  • The scan endpoint is rate-limited per client address.
  • Scan responses are marked no-store.
  • The browser sandbox is isolated from the API, with network isolation as the final boundary.

These controls reduce risk but do not eliminate it. DNS rebinding, provider compromise, and browser vulnerabilities are residual risks that any URL scanner must manage. The methodology page explains the limits.

What Zero Trace is not

  • It is not an antivirus, endpoint protection, or malware removal product.
  • It is not a guarantee that a URL is safe.
  • It is not a commercial service with an uptime or response-time guarantee.
  • It is not affiliated with VirusTotal, Google, or any security vendor.
  • It is not professional security, legal, or financial advice.

About the developer

Zero Trace is built and maintained by Mano Francis Dev, an independent developer who builds practical web and security tools. The project is public on GitHub, and the scanner’s behavior is documented rather than hidden behind marketing claims.

You can find the developer on GitHub, LinkedIn, or the portfolio.

Contact and contributions

For bugs, feature requests, or documentation corrections, open an issue on the Zero Trace GitHub repository. For a sensitive security report, do not post exploit details publicly; contact the maintainer through the GitHub profile so the issue can be handled privately.

Editorial and update policy

Guides and methodology pages are reviewed when the scanner’s implementation changes. Each long-form page shows an updated date. If you find an inaccuracy, report it through GitHub so it can be corrected. The site does not publish fake ratings, reviews, certifications, or security guarantees.
